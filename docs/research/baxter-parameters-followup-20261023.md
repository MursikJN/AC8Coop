## Установлено статически

`LiveSetIsInvincibleFromWingman`: class getter `146df1580`, constructor
`146dfd3a0`, vtable `14c66ea40`, execute `14740ed30`, initializer `1473ff0d0`.

| Смещение действия | Тип | Назначение, доказанное читателем |
| --- | --- | --- |
| +58 | FName, 8 байт | Выбор отдельного объекта через lookup в context+38 |
| +60 | FName, 8 байт | Сравнение с именем Unit через его интерфейс +2a0 |
| +68 | FName, 8 байт | Альтернативный выбор по группе Unit+1c8 |
| +70 | byte | Значение, записываемое выбранным объектам по +3fb |

Для Unit выполняется обход массива слабых ссылок живых дочерних объектов
`+2e0/count+2e8`, с проверкой serial/validity. Это не массив всех дочерних
объектов `+2c0`. Пустой список живых детей не передаст флаг новому самолёту.
Запись +3fb отличается от отражённого `bIsInvincible` по +3f8: эти поля
нельзя считать взаимозаменяемыми. Название команды не доказывает все условия
последующего расчёта урона; потребители отдельных флагов ещё не разобраны.

`LiveInputWingmanStateStatement`: getter `14706d980`, ctor `1470723a0`,
vtable `14cb10be0`, predicate `147ebc140`. Он преобразует строку FString
по +68 через `147ec4730`, получает WingmanManager мира и сравнивает его
byte +ba. Здесь нет выбора конкретного самолёта и чтения его AIState.

Enum getter `14706ef20`, descriptor `14dd94788`, таблица `14cb10000`
подтверждают `ELiveAIInputWingmanState`:
0=`FocusedAndForward`, 1=`Arbitrary`, 2=`Support`, 3=`Default`.
В отдельном `ELiveAIWingmanState` число 3 означает `Follow`.
Совпадение чисел не делает эти состояния одним контрактом.

Полные диапазоны readers/constructors проверены через PE/Capstone,
шесть диапазонов Ghidra побайтно совпали с офлайн EXE. Псевдотипы декомпилятора
не заявляются как ABI. Сырые данные находятся вне репозитория в приватном

## Приказ, повтор и фактическое состояние

Времена UTC обозначают первый срез с изменением. `input-markers.tsv`
ограничивает интервалы скрипта ввода, а не момент исполнения команды игрой.

| Первый срез UTC | Подтверждённое изменение | Бакстер AIState |
| --- | --- | --- |
| 01:40:39 | Исходные manager/system mode=3, RepeatCount=0 | Follow (3) |
| 01:41:15 | Первое прикрытие: manager и все три system mode=2 | Follow (3), в том числе после 20 с активного полёта |
| 01:41:53 | Повтор прикрытия: RepeatCount=1, mode=2 | Follow (3), ещё 15 с активного полёта |
| 01:42:29 | Режим не менялся, самолёты начали переход в прикрытие | Support (2) |
| 01:43:05 | Принята атака вперёд: manager/system mode=0 | FocusedAndForward (0) |
| 01:43:39 | Mode=0 сохраняется | Follow (3) |
| 01:43:59 | Mode=0 сохраняется | FocusedAndForward (0) |
| 01:44:01 | Принят возврат к прикрытию: manager/system mode=2 | Follow (3) |
| 01:44:41 | Mode=2 сохраняется | Support (2) |
| 01:44:53 | Принят повтор: RepeatCount=2, mode=2 | Support (2) в срезах |

Во всех принятых изменениях режима участвовали Бакстер, Таша и Коустер.
Это общий приказ звену, а не адресное переключение одного Бакстера.
RepeatFlag(+c5) всё время 0; смена режима не сбрасывала RepeatCount.
В последнем повторе Таша/Коустер дали наблюдаемое 2→3→2, а Бакстер остался 2.
Срезы не исключают более короткий ненаблюдаемый переход между опросами.

Две попытки ввода не дали изменения manager mode: `front_attack_start`
и `return_cover_start`. Следующие попытки приняли режимы 0 и 2 соответственно.
Название маркера `repeat_return_cover_start` не означает принятый повтор:
фактически это первая принятая смена 0→2. Повтор подтверждён отдельно в
`final_cover_repeat_start` счётчиком 1→2. Причина отклонения нажатий не доказана;
не объявляем её сетевой потерей, кулдауном или только задержкой выхода из паузы.

Итого: mode, repeat count и AIState — разные величины. Получено наблюдаемое
подтверждение, что AIState может меняться без нового принятого mode. Поэтому
первое Follow нельзя объяснять только слишком ранним срезом. Конкретное
условие выбора Support/Follow ещё требует разбора поиска целей и AI-модуля.

Дополнительный статический читатель `147eba1b0` (547 байт, полный диапазон)
при смене режима очищает старый модуль +f0, выбирает +f8/+100/+108 для
0/1/2 и вызывает его виртуальную инициализацию. Внутренние фильтры таблицы
+d8 со stride 0x28 сопоставляют эти режимы с кодами 2/3/1 соответственно.
Числа этой таблицы также нельзя подменять enum режима без отдельного анализа.
Функция не вызывается нашим наблюдателем.

## Что остаётся неизвестным

- Конкретные условия выбора AIState и причина непринятых обычных нажатий.
- Связи четырёх Support-условий с событиями: нужен отдельный ограниченный
  проход по нужным ветвям крупного контейнера, а не увеличение нагрузки вслепую.
- Потребители флага +3fb в расчёте урона, исполнение поздних действий и
  ненулевой repeat flag. Сетевая доставка и замена AI игроком не проверялись.

ТЗ и игровой мод не менялись. Изменён только read-only наблюдатель и его тесты.
