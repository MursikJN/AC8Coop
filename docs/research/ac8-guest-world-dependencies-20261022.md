# R31: зависимости мира гостя и регистрация самолёта

Дата: 22.10.2026. Только статический анализ через GhidraMCP и чтение PE.
Игра, native-функции и Steam-сессия не запускались. Комплект R31 не пересобирался.

Последующее изменение: обнаруженный ниже пробел предпроверки закрыт в
[R31 object-readiness-1](ac8-r31-object-readiness-20261022.md). Этот отчёт
описывает исходный исследовательский проход; его прежние хеши не относятся
к обновлённому ZIP.

Сверены с PE все 14 диапазонов `read_memory`, пять имён классов, четыре слота
vtable и две непосредственные команды call. Это проверка исходных доказательств,
не автономный тест работы игрового мира. Ghidra иногда объединяет хвосты функций
и неверно восстанавливает параметры/возврат; точный ABI нельзя выводить из одной
строки псевдокода. Пустой call graph не считается отсутствием вызовов.

## Поправка к прежней терминологии

`GameInstance+908` создаётся с классом из `0x1470078d0`; имя по
`0x14ca59ce2` — **LiveSoundManager** (ответы 018, 035, 038).
`0x1478a4620` создаёт его дочерний объект `+1a8` и использует конфигурацию,
переданную из `GI+828` (021, 024). Сверены команды:

- `0x1478dc395`: загрузка `R8` из `[R14+828]`;
- `0x1478dc39c`: загрузка `RCX` из `[R14+908]`;
- `0x1478dc3a3`: call `0x1478a4620`.

Это звуковая зависимость BeginPlay, а не доказательство наличия менеджера сцены.
При очистке GI путь `0x1478df820` вызывает `0x1478a5160` для этого объекта
и очищает поле (013, 017). Сам конструктор GI лишь обнуляет поля (005, 016).

В текущем `native/guest_owner_native.inl` имена `scene_manager` и `object_mapper`
относятся к этой звуковой цепочке. Причина `owner_beginplay_scene_manager_missing`
означает отсутствие звуковой зависимости. Сами адреса чтения этой поправкой
не опровергнуты. Старые отчёты и готовый ZIP сохранены как история.

Настоящий **LiveObjectMapper** находится по `LiveActorManager+1b0`:
класс `0x146f8e9b0`, имя `0x14c99293a` (032, 040, 044).
`GI+878` — **LiveInformationManager** (039, 042).

## Создание и готовность менеджера акторов

Constructor wrapper `0x146d08920` переходит через `0x157932370` в
`0x1473a13d0`; внутренние `+1a0/+1a8/+1b0/+1b8` сначала нулевые
(006, 019, 020). Родитель — `LiveWorldSubsystem` (007, 026, 027).

Vtable `0x14c4b2450`:

| Слот | Адрес | Установленное поведение |
| --- | --- | --- |
| +2b8 | `0x1473ad190` | Проверка допустимости внешнего World / LiveGameInstance |
| +2c0 | `0x1473acfe0` | Подписка на глобальные делегаты мира |
| +2c8 | `0x1473ad0d0` | Снятие этих подписок |
| +308 | `0x1473a1620` | Инициализация привязанных к миру объектов |

В predicate числовой `WorldType==2` допускается напрямую; иначе проверяется
тип `World+1d8` на `LiveGameInstance`. Проверки campaign GameMode в этой
функции нет (028, 051). Это поддерживает выбранный путь generic мира, но
не доказывает, что subsystem collection его создаст в нужный момент.

Callback `0x1473ad250` проверяет совпадение World с внешним миром менеджера
и вызывает virtual +308 (037). В `0x1473a1620` для типов из маски `0x6a`
(включая числовой тип 1) создаётся **LiveCombatZone** в `manager+1a0`, если
его ещё нет; затем вызывается `0x1473a2820` (031, 041, 045).

Последняя функция создаёт объекты `+1a8`, `+1b0` и `+1b8`; mapper по `+1b0`
получает контекст из `CombatZone+308` (032, 054). Поэтому объект менеджера
может уже существовать, когда его зависимостей ещё нет.

При регистрации `0x1473a1a80` добавляет самолёт в список `manager+128`,
подписывает callback `0x1473a3e20` на `plane+700`, затем использует
`manager+1b0` для регистрации объекта (012). Чтение mapper в этом пути
не защищено отдельной проверкой его наличия.

**Пробел R31:** текущая предпроверка native backend проверяет identity
ActorManager, но не готовность его `+1a0/+1b0`. До первого создания самолёта
рекомендуется добавить отдельный read-only gate: тип/identity/World этих
объектов и сохранность связи на игровом потоке. Если они не готовы — ждать
ограниченное время либо завершать подготовку с точной причиной, не продолжать
FinishSpawn/BeginPlay. В этом исследовательском проходе код поставки не менялся.

## FlightData и ресурсы

Lifecycle GI создаёт `LiveInformationManager` и вызывает `0x1473451e0`
с конфигурацией GI (018, 034). Загрузчик `0x1473468d0` заполняет индексы
по именам/числовым ключам из таблиц (048); одной этой функции недостаточно,
чтобы утверждать наличие конкретного загруженного F-14D asset.

Инициализация самолёта `0x147d4af60` связывает класс с PlaneTypeID, получает
данные через `0x147360970/0x1473610b0` и записывает FlightData в `plane+3ab0`.
В одной ветви выбирается строка 0, в другой индекс зависит от профиля;
индекс ограничивается числом строк. Видимый шаг строки — **0x448**,
не десятичное 448 (043). Текущий R31 использует строку 0 и не вычисляет этот шаг.

Указатель из `0x147edb4e0` допускает отсутствие результата: init обнуляет
соответствующую weak-ссылку (043, 050). Это снимает одну локальную зависимость,
но не доказывает независимость всей физики от campaign session/controller.
Псевдокод getter 053 не восстанавливает полноценный возврат; он не заменяет
ранее выполненную проверку ABI в отчёте native R31.

## Снятие регистрации и дочерние объекты

Штатный EndPlay `0x147d24a40` в ветви begun и `plane+dfa==0` транслирует
событие `plane+700` через `0x1417015d0`; команды по `0x147d24a74/7e`
сверены с PE (052, 055). Другая ветвь идёт через `0x147d24b40`.

Подписанный `0x1473a3e20` собирает самолёт и дочерние объекты, вызывает
`0x1473a4250`, затем подписывает обработчик `0x1473a4120` на `plane+718`
(036). Функция `0x1473a4250`:

- снимает запись mapper по ObjectIndex, включая индексы `+60/+b0`;
- снимает callback корневого компонента;
- удаляет указатель из классификационных списков `+138/+148/+158`;
- удаляет его из общего списка `+128`, уменьшает соответствующие счётчики;
- очищает `manager+1e0`, когда он указывает на этот самолёт (046).

Обработчик `0x1473a4120` снимает свою подписку, обходит связанные объекты,
вызывает путь World Destroy для остальных и `0x147d24b40` (049).
Не нужно вручную повторять эти действия поверх штатного EndPlay.
Это не доказательство сборки мусора: bool Destroy, снятие регистрации и
фактическое освобождение UObject — разные наблюдения.

## Следующий ограниченный эксперимент

До игрового теста закрыть указанный пробел предпроверки в новой согласованной
сборке; сам текущий архив в этом проходе неизменен. Затем в изолированной копии
сначала зафиксировать World/manager/CombatZone/mapper identity и FlightData,
после единственной попытки spawn — BeginPlay и регистрацию, после выхода —
EndPlay, снятие mapper/списков и retirement. При провале остановить подготовку.
Не включать повторный spawn в том же процессе и не обходить preflight.

В этой работе не проверены управление, камера, два ПК, синхронизация сюжета,
реальный GC и отсутствие крашей. UE4SS MCP в текущем перечне инструментов нет;
для разрешённой статической работы использован доступный GhidraMCP.

ZIP R31 остаётся с SHA256
`db9dd759be1af3c8e08096c50d87e0ded543c3ada5d78cb585263bee10c82e5d`.
