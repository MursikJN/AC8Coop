## Что запускать при следующей проверке

`C:\Users\Administrator\Desktop\ACE\profiles\ac8-mission6-capture\Start-Mission6Capture.cmd`

Он использует уже проверенную копию:
`C:\Users\Administrator\Desktop\ACE\ac8-steam-coop-r31-compact\lab-game`.
Ещё одна копия игры на 5 ГБ не создаётся. Наблюдатель и launcher находятся
в отдельном профиле, каждый запуск получает отдельные runtime, сохранения и журнал.
Обычный `Start-Host.cmd` / `Start-LocalModelTest.cmd` для этого опыта не нужен.

1. Закрыть игру и предыдущий лаунчер обычным выходом.
2. Перевести Steam в автономный режим. Не открывать сетевые режимы игры.
3. Запустить указанный CMD. На запрос подтверждения автономного режима ввести
   `OFFLINE`. Enter без этого отменяет запуск.
4. Нажать Enter на титульном экране. Открывать кампанию штатно, без кооп-меню.
5. Выбрать задание 6 и записать выбранную сложность. На первый проход оставить
   обычный состав ведомых; Бакстеру выбрать F-14D. Игрока не подменять.
6. Пройти маршрут: главное меню → выбор задания → брифинг → ангар → подготовка
   вылета → вступительная сцена → управляемый полёт.
7. На устойчивых экранах нажать **F8 один раз**: главное меню, ангар, подготовка
   вылета, первый управляемый полёт. Автоматические снимки тоже сохраняются.
8. В полёте один раз отдать обычную команду Бакстеру, дождаться реакции, нажать F8.
   Указать затем, какую именно команду отдали. Не использовать диагностические
   F9/подмену самолёта из старых профилей.
9. Выполнить штатный перезапуск задания, дождаться управляемого полёта, F8.
   Вернуться в меню обычным способом, F8, затем выйти из игры и дождаться лаунчера.
10. Если снимки заметно мешают работе игры, **F10** останавливает наблюдатель
    до следующего запуска. Он не снимает и не ставит игровую паузу.

Не нужно проходить всё задание ради первого набора. Отдельный второй проход
с завершением брифинга естественным образом/пропуском и со штатным завершением
миссии нужен после анализа первого набора. Эти ветви не считать покрытыми
одним выходом в меню.

`C:\Users\Administrator\.codex\visualizations\2026\10\20\01a1584d-af0f-7d72-8611-ec65cbfc74e4\ac8-research\mission6-runtime\session-*`

- `runtime/UE4SS.log`: ошибки загрузки/API. Аварийный дамп, если его создаст UE4SS,
  остаётся в этой же частной сессии.

Для первичного разбора достаточно `session.json`, `observations` и `UE4SS.log`.
Не публиковать извлечённые строки таблиц, сохранения, дампы и игровые ресурсы

## Ограничения и защита от неверных выводов

Сборщик читает reflection на игровом потоке и не вызывает игровые UFunction.
Между снимками сохраняются только строки; ссылки на UObject, строки таблиц и
обёртки контейнеров после завершения снимка не используются повторно.
Проверяются CDO, тип обёртки, лимиты и доступность данных.

Опрос контекста раз в 2 секунды; снимок при изменении наблюдаемых world/object/state
полей, раз в 30 секунд и по F8. Это **выборка, а не точный журнал всех callbacks**:
короткую промежуточную фазу она может пропустить. Время UTC — время наблюдения.
Лимиты: 256 объектов, 2048 элементов контейнера/строк таблицы, 30000 строк вывода,
глубина 5 и мягкий бюджет CPU 0,25 секунды между операциями. Native-вызов API
UE4SS невозможно прервать этим бюджетом; небольшой рывок кадра возможен.

`summary=traversal_finished` означает завершение обхода, а не полноту графа.
`gap`, `aborted`, `fatal`, `context_changed=true` требуют разбора. Нулевой результат
FindAllOf не означает отсутствия механизма. `Mission007` в имени не доказывает,
что объект принадлежит активному миру: в памяти могут оставаться загруженные assets.
Нерефлексивные private native-поля и shared-pointer записи не читаются по офсетам.
Если важный контейнер окажется скрыт, следующий шаг — его отдельный проверенный
read-only декодер, а не подстановка адреса или неподтверждённый native-вызов.

API UDataTable/TMap подтверждены по локальным исходникам UE4SS и наличию имён
в используемой DLL; их работа именно с таблицами этой игры ещё не наблюдалась.

Лаунчер проверяет отдельность EXE, build/hash, отсутствие конфликтующих загрузчиков,
plain paths и компактный архивный layout. Во время работы держит исходные общие
архивы открытыми только на чтение с запретом записи/удаления через junction.
Прогресс копируется однократно в отдельную папку запуска, обратно не переносится.
Steam Offline подтверждает человек; OS-блокировка сети не устанавливается и не
объявляется проверенной. При обнаружении NetDriver наблюдатель прекращает сбор;
он не отключает уже существующее соединение и не служит сетевым изолятором.

Повторная подготовка: `scripts/Prepare-Mission6Capture.ps1 -ProfileRoot <новая папка>`.
Без `-Launch` файл `Start-Mission6Capture.ps1` выполняет только preflight.

### Ввод, который сработал на карте брифинга

В текущем видимом запуске проверен `universal-modder` WinDrive: `scanmode on`,
затем `hold 0x20 150` (пробел на 150 мс), по одному нажатию с проверкой экрана.
Шесть нажатий последовательно меняли цель на карте. Для выхода с этой карты
сработало `hold 0x1B 150` (Esc); наблюдатель зарегистрировал загрузку PL_Hangar002.
Обычные короткие нажатия через Computer Use здесь не дали перехода.

Перед вводом проверять, что активен именно единственный процесс изолированной
игры. Не использовать слепую серию и не выводить окно через MainWindowHandle:
у этого процесса он может указывать на вспомогательное окно ввода. Для выбора
UnrealWindow использовать актуальный список окон Computer Use. Успех проверен
для сочетания скан-кодов и удержания; причина различия отдельно не измерялась.

Скан-коды с удержанием150мс работают также для стрелок, Enter и Space в выборе

разрешением для следующего запуска: дождаться конца лаунчера и очистки.

## Сбор по небольшим проходам (v2)

Новый профиль сначала обнаруживает имена объектов одной категории, затем читает
по одному объекту за тик (2секунды). На первом месте события и индексированные
таблицы. Между тиками остаются только строки имён; UObject получается заново.
Смена контекста сбрасывает очередь. F8 делает следующий проход либо запускает
новый цикл, F10 прекращает наблюдение. По завершении цикла пауза30секунд.

Файлы discovery_finished содержат список имён, а single_root — поля одного
объекта. Ссылки записываются без рекурсивного обхода; разные файлы не являются
атомарным снимком всего мира. traversal_finished нужно оценивать вместе с scope,
gap и context_changed. Бюджет чтения0.25CPU-секунды сохранён; сбор контекста
выполняется отдельно до/после. При раннем ограничении данные остаются частичными.
