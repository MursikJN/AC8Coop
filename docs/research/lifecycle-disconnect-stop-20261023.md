# Остановка мира при потере тестового гостя

Профиль: `profiles/ac8-lifecycle-stop-v4`. Одна изолированная игра хоста,
один headless-клиент с настоящим native loopback transport. Производственный
комплект r31 и оригинальные игровые файлы этим профилем не обновляются.

## Контракт

- Включение только через `Start-LifecyclePair.ps1 -HeadlessGuest -StopOnDisconnect`.
- Удержание разрешается после наблюдения активного самолёта задания 6 и
  согласованной фазы flight с подключённым гостем.
- Проверяется формат локального статуса, token текущего запуска, роль host,
  наличие snapshot, epoch. Старые epoch не принимаются.
- `stopped / peer_lost` фиксирует необратимый для этого запуска запрос остановки.
  Зависание публикации статуса на 5 секунд после взведения также вызывает остановку.
- Все обращения к UE выполняются в игровом потоке. Используется существующий
  guarded native pause adapter: идентичность UObject, serial, vtable, backlink,
  отпечаток функции штатного PauseManager. Новых адресов/офсетов не вводится.
- Пауза использует штатный бит `0x20`, который Update учитывает даже при
  ненулевом override. Счётчик override не меняется. Если этот бит уже установлен
  игрой, мод не присваивает его; остальные причины остаются неизменными.
- После ошибки native-вызова дальнейшие обращения прекращаются, ошибка сохраняется.
- Подключение/повтор пакета не снимает удержание. Автоматического продолжения
  после обрыва пока нет; нормальный выход завершает лабораторный процесс.

## Проверки до запуска

13 Lua/Lupa tests (9 stop policy + 4 observer), 12 native channel tests,
20 existing mission adapter tests; 7 C++ pause ownership checks + 6 disconnect checks,
17 C++ bootstrap checks. MSVC x64 /W4 /WX сборка pause DLL.
19 фиксированных отпечатков проверены по read-only изолированному EXE;
префикс pause update уникален в исполняемых секциях.

## Живая проверка

Первый проход v3 (`pair-20261023-070722`, host14424/guest17260) выявил отказ:
во время дозаправки flags=0, override=2, paused=0. Обычная SafeMode-пауза
не применялась. Это НЕ успешная остановка. Оба процесса завершились штатно,
exit0; loader удалён. Первый преждевременный вызов проверки lobby также
отклонён до появления меню, без отправки команд; повтор после загрузки прошёл.

H-STOP-OVERRIDE-01: GhidraMCP get_program_info подтвердил offline EXE SHA256
`51510e2a520565dbe81fb0d569e95cd4393077acaaa859371489b80b8128829f`, base
`0x140000000`. Decompile + read_memory 256 bytes VA `0x1479163f0` подтверждают
ветвление: flags +0x28, applied +0x2c; при отсутствии bit5 и override +0x34 !=0
результат pause=false, иначе flags!=0. Инструкции проверены Capstone по тем же
байтам (Ghidra disassemble вернул пустой список, это ограничение не скрыто).
Native lab guard дополнен двумя 16-byte проверками RVA 0x7916407/0x7916417.
Название enum для bit5 не установлено; поведение подтверждено инструкциями.
Сырые материалы сохранены вне репозитория, в каталоге первого прохода:
`pause-ghidra-analysis.json`, `pause-instructions.txt`.

v4 — отдельная сборка `AC8_DISCONNECT_PAUSE`, которая дополнительно требует
маркер окружения лаборатории. Обычная сборка r26 сохраняет причину 8 и отказ
при override; производственный комплект не заменён. В Lua исправлена также
повторная запись loss_detected на каждом опросе уже остановленной сессии.

Второй проход v4 (`pair-20261023-072357`, host24408) — **PASS**. Лобби,
брифинг, ангар, вылет пройдены тем же штатным маршрутом; задержки гостя и
повтор готовности/команды запуска прошли. После закрытия учебной подсказки
самолёт двигался, paused=0. Первый запрос disconnect пришёл до обновления
наблюдателя после закрытия подсказки и был отклонён локальной проверкой;
гость тогда не отключался. Повтор после свежего paused=0 выполнил обрыв.

- Native session: phase8, stop_reason3.
- Engine: flags32, applied32, held1, paused1, **override2 сохранён**.
- Подтверждение остановки через 1.688 секунд после команды остановки гостя.
  Это включает период опроса наблюдателя и не равно чистой сетевой задержке.
- После подтверждения: world_time=23.907648494467 неизменно, позиция
  (143148.64625864, 74.000074452621, 599522.38628947) неизменна на проверочном
  интервале 8 секунд; смещение=0, прирост игрового времени=0.
- Повторные опросы не снимали удержание, журнал переходов содержит ровно
  armed → loss_detected → held. Нет зацикленной записи acquire.
- Наблюдатель продолжал обновлять UTC, приложение отвечало и рисовало кадры.
  Это пауза мира, не зависание процесса.
- Дополнительные снимки с интервалом 39 секунд подтвердили прежние координаты
  и время; экранный таймер дозаправки на обоих кадрах `02:50:47`.
- Обычный Alt+F4: host24408/guest10884 завершились с кодами 0, loader удалён.
  Завершение второго прохода: 2026-10-23 07:39:11 UTC. Игровых процессов нет.
- SHA256 оригинального EXE после обоих проходов совпадает с исходным;
  оригинальный loader отсутствует. Shared archives удерживались read-only guard.
  Полный побайтовый аудит оригинальной установки не выполнялся.

Индекс доказательств: [lifecycle-disconnect-stop-20261023-evidence.json](lifecycle-disconnect-stop-20261023-evidence.json)
(49 частных артефактов с хешами; 9 файлов профиля совпадают с загруженным runtime).

Границы: headless-клиент не рисует второй мир. Отдельно потребуются проверки
на настоящем госте, в бою, при переходах уровней и при конфликте со штатными
диалогами. Механизм требует работающего игрового потока; аварийное зависание
всего процесса не лечит. Не проверены все события, использующие real-time
таймеры вместо game-time. Проверка одного мира не доказывает синхронизацию
двух игровых сцен. Автоматическое возобновление и освобождение lease во время
перехода уровня не реализуются этим профилем; тест завершается обычным выходом.
