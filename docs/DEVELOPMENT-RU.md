# Разработка и воспроизводимость

**Актуальная передача на 23 октября 2026:** [HANDOFF-RU.md](HANDOFF-RU.md) — состояние, карта кода и сборка lifecycle-stop. Ниже сохранены в том числе исторические инструкции; сверяйте версию и профиль.

Публикация — исходный снимок лаборатории. Большинство живых скриптов пока привязаны к `D:\projects\unreal-mod-tools`, профилю `ac8-build25201480`, известной сборке игры и проверенным хешам. `C:\Users\USER` в исторических файлах — заменённый личный путь, не готовая настройка. Скрипты с PID/адресами старой сессии служат материалами исследования, запускать их для нового процесса нельзя.

## Проверки без запуска игры

Используется Python 3.11+ и Lupa 2.6. Из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
```

Capstone нужен скриптам статического анализа. Некоторые исторические тесты добавляют старую локальную папку в sys.path; установленные в venv пакеты всё равно доступны. Тесты моделируют память/вызовы и не создают самолёт в игре.

Тест фактической загрузки транспортной DLL выполняется только при заданном `AC8_CONNECTION_NATIVE_TEST_DLL` с путём к собранной Connection Test DLL. Если переменная не задана, этот один тест пропускается; старый локальный путь автора больше не используется. В ограниченном процессе Windows Lupa может получать отказ в доступе к временным каталогам — это проблема тестового окружения, а не доказательство неисправности зонда.

Для нативного полётного модуля нужны Windows x64 и Visual Studio Build Tools с C++:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build-PlaneFlightProbe.ps1 -OutputRoot "$PWD/build/plane-flight-r6"
```

Команда собирает `ac8_plane_flight_probe_r6.dll` и выполняет нативные проверки без старта игры. По умолчанию результат помещается в `build/plane-flight-r6`. Поддерживается обнаружение предварительной версии Visual Studio Build Tools. Результат сборки не устанавливается автоматически. Хеш DLL может отличаться из-за пути или версии компилятора. Launcher требует явный `-PlaneFlightHash` для проверенного r6-артефакта.

Для подготовки отдельного профиля распакуйте официальный UE4SS `3.0.1-1181-g83330635` в `packages/ue4ss-3.0.1-1181-g83330635` (внутри должны быть `dwmapi.dll` и `ue4ss/UE4SS.dll`), затем выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Prepare-PlaneFlightTrial.ps1 -GameDirectory 'D:\Programs\Steam\steamapps\common\ACE COMBAT 8\Game\Binaries\Win64'
```

Скрипт проверяет хеши EXE и proxy, создаёт новый `profiles/ac8-build25201480-r6`, копирует только исследовательский мод и необходимые файлы runtime, фиксирует хеши DLL в `Start-R6.ps1` и выполняет `ValidateOnly`. Существующий профиль не перезаписывается. Файлы игры при подготовке не меняются. Для другой подготовки укажите новый `-OutputRoot` непосредственно внутри `profiles/`. Исходный профиль автора использовал zDEV-пакет. В сессии r5 со стандартным upstream runtime этой же версии подтверждены загрузка UE4SS, работа F8 и native preflight. Вызов setter и видимость пока не подтверждены.

`Start-R6.ps1 -ValidateOnly` повторяет проверки без запуска; `Start-R6.cmd` запускает опыт. Launcher временно размещает proxy возле игры и удаляет его после выхода. Если запуск прервался, используйте `Remove-ReconLoader.ps1 -GameDirectory '<папка с AceCombat8.exe>'` после закрытия игры. F7 по-прежнему требует отдельного токена, привязанного к результату F8; подготовка профиля не создаёт токен.

Для `Build-ConnectionTest.ps1` отдельно нужны заголовки Valve GameNetworkingSockets указанной в THIRD-PARTY ревизии; путь передаётся через `-ValveHeaders`. Они и UE4SS не включены в Git.

## Живой запуск

Нужны собственная установленная игра точной сборки, Steam, подготовленный профиль UE4SS, собранная DLL и согласованные пути/хеши. `Start-PlaneFlightProbe.cmd` из папки scripts рассчитан на установку рядом с профильным `Launch-Recon.ps1` и принимает параметры запуска, включая `-PlaneFlightHash`. Для нового отдельного профиля используйте процедуру выше. Подготовка и `ValidateOnly` подтверждают комплектность файлов, но не загрузку runtime или видимость в игре.

Публичный Connection Test больше не содержит ваших SteamID: launcher спрашивает ID второго участника, упаковщик создаёт пустые поля peers. Числа в mock-тестах синтетические. Существующий персональный архив 0.1.2 и установленные настройки участников этой публикацией не менялись.

## Замеры r6

После единственного опыта откройте `plane-flight-cadence-r6.json` из текущей папки evidence. Файл содержит ограниченный буфер до 4096 кадров и сохраняется при остановке, без пофреймовой синхронной записи. Запустите:

```powershell
python scripts/analyze_plane_flight_cadence.py '<папка сессии>/plane-flight-cadence-r6.json'
```

Интервалы в файле измерены QPC в микросекундах; позиции — в сантиметрах UE. Анализатор переводит их в миллисекунды и метры. `state_us`, `model_us`, `pose_us` разделяют стоимость подготовки состояния, native Update и применения позы с проверками/редкими снимками. Общий интервал между callback включает также планирование и работу после native motion. Поправки по позе и манёвры могут увеличивать рассчитанный остаток линейного прогноза; автоматического заключения о причине тряски нет. Журнал `plane-flight-lifecycle-events-r6.tsv` больше не содержит строку для каждого шага, поэтому его нельзя использовать для оценки кадровой частоты r6.


## R7: подготовлен первый опыт с двумя участниками

R7 передаёт проверенное числовое состояние второго игрока через Steam и подаёт его в собственную копию вместо состояния локального игрока. Создание требует готовности обоих, отдельных токенов и F7 на каждой машине. Нативное движение ограничено 15 секундами; F9, устаревание, смена поколения или потеря связи останавливают опыт. Прежние барьеры обновления и проверки удаления сохранены. Живой совместный полёт r7 ещё не проверен.

Сборка: `scripts/Build-CoopFlightProbe.ps1`; профиль: `scripts/Prepare-CoopFlightTrial.ps1`; переносимый пакет: `scripts/package_coop_flight.py`. Инструкция: `coop/README-RU.md`; результаты автономных проверок: `docs/research/plane-flight-r7-validation.json`. Успешная r6 сохранена отдельно; её выход с кодом 0 и удаление proxy подтверждены финальным session.json.
