# r28 — локальные катсцены и ожидание второго игрока

Экспериментальная сборка для ACE COMBAT 8, Steam build 25201480. Оба участника
должны использовать r28: протокол 6, приглашения v6, отдельный Steam virtual port 390.
Приглашения r27 с этим профилем несовместимы.

## Порядок

Лобби → готовность обоих → локальное вступление/брифинг → ангар → новая готовность
→ загрузка миссии → локальная внутриигровая катсцена → совместный полёт.
Задание 6, сложность ПИЛОТ, F-14D гостя остаются первым поддерживаемым маршрутом.
Самолёт хоста выбирается в штатном ангаре.

- Перед каждой сценой передаётся идентификатор локального игрового ресурса.
  Видеопоток и звук с компьютера хоста не пересылаются.
- Каждый плеер подтверждает свою подготовку; начало согласуется по часам хоста.
- Удержание Esc даёт один голос текущей сцене. Одного голоса недостаточно.
  После двух голосов согласуется момент пропуска, затем требуются оба подтверждения.
- При обычном просмотре ранний участник удерживает терминальный участок сцены
  и ждёт второго. После обоих подтверждений согласуется отпускание этого участка.
  Штатный переход хоста допускается после реального экрана завершения.
- Повтор команды не перезапускает плеер; подтверждения предыдущей сцены,
  старой редакции или другой попытки подключения не открывают переход.
- Потеря ресурса или неподдерживаемая сцена блокирует переход и сохраняет ошибку.

## Что ещё не проверено

**Игру при подготовке r28 не запускали. Полёт и катсцены на двух ПК не приняты.**

Написаны адаптеры штатного LiveManaMovieViewer (видео, текстура, выбранные видео-
и аудиодорожки) и LiveCinematics (штатные голосовые/видео-треки). Для LiveCinematics
нужен найденный локальный ресурс с настоящими SequenceOptions и ссылкой на эту сцену.
Пустые параметры окружения не подставляются. Если такого ресурса не удастся найти,
потребуется уточнить привязку по журналу завтрашнего запуска.

Сохранённая диагностика подтверждает наличие API, но не содержит идентификаторов
всех активных клипов и не доказывает корректность их запуска на госте. Пока не
проверены совместимость Lua binding с OnFinished=nil, штатный звук, создание
виджета видео, готовность камеры Sequencer, пауза и переходы на реальном брифинге.
Терминальная задержка до 250 мс перед концом требует проверки на звуке/плавности.
Обычный LiveMovieViewer и брифинг без Mana/LiveCinematics автоматически не имитируются.

## Запуск проверки позже

1. Закрыть предыдущую игру обычным выходом, распаковать архив в отдельную папку.
2. Хост запускает `Start-Host.cmd`, гость — `Start-Guest.cmd`; оба загружают профиль.
3. Создать лобби и пригласить друга штатной кнопкой Steam. Для проверки с имитатором
   он также должен реализовать новые подтверждения сцен; старый имитатор r26/r27
   не является готовым вторым видеоплеером и не должен открывать барьер.
4. При остановке смотреть `cinema-playback-status.tsv`, `cinema-host.tsv` /
   `cinema-client.tsv`, `shared-session-status.tsv`, `steam-menu.log` в `evidence`.

Лаунчер сохраняет отчёт и резервную копию профиля, как в r27. Не устанавливать DLL
в уже работающий процесс. Никакой запуск игры не входит в автономную сборку.
