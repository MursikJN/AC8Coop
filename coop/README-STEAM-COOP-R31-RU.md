# AC8Coop R31 — экспериментальный комплект первого полётного теста

Windows x64, Steam-сборка игры **25201480**, два ПК и разные Steam-аккаунты.
В комплекте одинаковые файлы для хоста и гостя. **Совместный полёт ещё не
подтверждён в игре.** Проверены сборка и автономные сценарии; native bootstrap,
камера, освобождение объектов и весь маршрут на двух ПК требуют испытания.

Текущая поправка комплекта — **compact-2**, включая **object-readiness-1**.
В compact-1 обнаружен ранний I/O-краш: ссылки на отдельные архивы возвращали
нулевые размеры Win32. В compact-2 используется одна проверяемая точка
соединения (junction) только для `Game/Content/Paks`, а размеры всех архивов
проверяются до запуска. Исправление проверено без запуска игры; успешный вход
в главное меню и совместный полёт ещё предстоит проверить.
Она проверяет зависимости
самолёта до его создания и повторно перед BeginPlay. Если CombatZone или
LiveObjectMapper ещё не готовы либо сменился мир, подготовка останавливается
с причиной `owner_world_…` в отчёте. Это не подтверждение готовности всех
игровых ресурсов. **Оба участника должны распаковать обновлённый ZIP заново**
в отдельные папки; старые r31 DLL/Lua не подмешивать.

Сценарий: задание **6**, сложность **«ПИЛОТ»**, гость на **F-14D вместо Бакстера**,
два других ведомых под AI. Хост выбирает свой поддержанный самолёт и ведомых.
Для гостя поддержано стандартное вооружение, без модификаций. Бой, попадания
и полное прохождение кампании не приняты. Это комплект для диагностики.

## Один раз на каждом ПК

1. Распакуйте ZIP в отдельную доступную для записи папку. Оставьте прежнюю r29
   отдельно. Не копируйте файлы r31 поверх других версий или в Steam-папку.
2. Запустите **Validate-Kit.cmd**. Это только проверка комплекта: игра, помощник
   и Steam-соединение не запускаются. При ошибке не начинайте полётный тест.
3. Запустите **Prepare-Lab.cmd**, выберите исходную папку `ACE COMBAT 8`, внутри
   которой есть `Game` и `Engine`. Для junction обычно не нужны права
   администратора или режим разработчика Windows.
   Скрипт проверит сборку и подготовит компактный `lab-game`: примерно **5 ГБ**,
   рекомендуемый запас **6–8 ГБ**. EXE/DLL и прочие файлы копируются отдельно,
   а большие `.pak/.utoc/.ucas/.sig` из Game/Content/Paks читаются через одну
   строго проверяемую junction этой папки. Другие ссылки и hardlink запрещены.
   Подготовка не меняет исходные файлы, их attributes или ACL.
4. Если исходная папка содержит загрузчик другого мода, закройте прежний
   лаунчер обычным способом или используйте чистую исходную копию.
   Существующий/неполный `lab-game` не перезаписывается. При прерванной
   подготовке сохраните эту папку для разбора и распакуйте комплект заново
   в другую папку. Скрипт ничего не удаляет автоматически.
5. Запустите **Validate-Lab.cmd**: проверит комплект и подготовленную игру,
   не запуская её. Только после успешного результата переходите дальше.

### Если compact-1 уже подготовлена

Закройте игру и прежний лаунчер обычным способом. Распакуйте compact-2 во
временную отдельную папку, затем скопируйте **только файлы комплекта из ZIP**
в прежнюю папку compact-1 с заменой. Не копируйте никакие игровые файлы и
не заменяйте `lab-game`, `userdata`, `reports`, `evidence` или `save-backups`.
Запустите **Repair-Lab.cmd**, затем **Validate-Lab.cmd**. 5 ГБ повторно не
копируются; сохранения и обычные файлы остаются на месте. Проверенные старые
ссылки сохраняются в `compact1-links-backup-*` для восстановления; новые
запуски их не используют. При ошибке смены структуры скрипт восстанавливает
старую, запускать игру в ней не нужно. Повторный Repair-Lab безопасно проверит
уже исправленную папку.

`lab-game` и настоящие сохранения не входят в ZIP. Каждый пользователь готовит
свою папку из собственных файлов. Исходную установку нельзя удалять/перемещать:
из неё читаются большие архивы. Не редактируйте общие архивы через lab-game.
Во время игры лаунчер держит read-only handles, блокирующие обычную запись
данных/удаление архивов. **Не закрывайте окно лаунчера до выхода из игры**:
защитные handles принадлежат ему. Steam-обновления выполняйте после выхода.
Папка Paks — прямой путь к исходным архивам: не добавляйте, не удаляйте и не
редактируйте там файлы вручную. Защита удерживает существующие архивы и точку
соединения; это не файловая песочница и не запрет создания новых файлов другим
кодом. Подготовка и проверка не меняют содержимое, атрибуты или ACL оригиналов.
Для подготовки через PowerShell доступен
`Prepare-CoopLab.ps1 -SourceGameDirectory "D:\...\ACE COMBAT 8"`.
Предварительный расчёт без копирования: добавьте `-PlanOnly`.
Полная отдельная копия остаётся доступной через `-StorageMode Full` при наличии места.

## Запуск вдвоём

1. Закройте прежний процесс игры обычным выходом. Запустите Steam, войдите
   под своими аккаунтами, добавленными друг к другу в друзья.
2. Хост открывает **Start-Host.cmd**, гость — **Start-Guest.cmd**. Лаунчер
   использует только проверенный `lab-game`; подставить оригинальную папку
   через параметр запуска r31 нельзя. Окно лаунчера оставляйте открытым.
3. На титульном экране каждый нажимает Enter обычным способом и ждёт главного
   меню. Дальше следуйте **TEST-PLAN-RU.md** из этого же комплекта.
4. Хост создаёт лобби через «Совместная игра», нажимает «Пригласить друга».
   Гость принимает приглашение в уже запущенной игре. Запасной путь — вход
   по SteamID64 **хоста**. Гость не запускает свою кампанию.
5. Два этапа готовности: сначала лобби, затем после ангара. Миссию запускает
   хост. Катсцены идут локально: 1/2 голосов недостаточно, пропуск только 2/2;
   если один досмотрел раньше, он ждёт второго.

Управление гостя в этом кандидате: стрелки — тангаж/крен, Q/E — рыскание,
W — газ, S — тормоз; также предусмотрен XInput-геймпад. Считывание активно
только при фокусе на игре. Пользовательские переназначения/джойстики напрямую
из настроек игры этим маршрутом не подтверждены. Хост управляет штатно.

## Сохранения и повтор

Прогресс хоста сохраняется в `userdata` **этого комплекта**. Прогресс гостя
изолирован в папке конкретной попытки и для следующей не используется.
При первом запуске копируются исходные Config/SaveGames, originals не меняются.
Автоматического переноса прогресса обратно в обычную установку нет.

Native создание — одна попытка на процесс. Общий restart поддерживает новый
процесс с возвратом в лобби; титульный Enter может потребоваться снова.
При quarantine/отказе не нажимайте старт многократно: сохраните отчёт,
закройте игру обычным выходом и начните новую попытку. Гость после гибели
наблюдает до общего перезапуска; это также нужно проверить.

## Локальный тест одной игрой, без друга

**Start-LocalModelTest.cmd** запускает отдельный лабораторный сценарий гостя.
После Enter и главного меню он сам загружает изолированную сцену задания 6.
Помощник `Owner-Lab-Peer.exe` обменивается пакетами только по 127.0.0.1,
не подключается к Steam и не рассчитывает полёт. Реальная игра создаёт F-14D
через тот же native backend, который использует сетевой гость.

Начальные условия намеренно тестовые: XY текущего Pawn, высота +1500 м,
горизонтальное направление +X, скорость 250 м/с. Это не записанный мир хоста
и не доказанное безопасное место появления. Для отмены и проверки очистки
нажмите **F9** один раз, затем выйдите из игры обычным способом. Помощник
имеет предельное время работы 30 минут; ограничение не относится к совместной
миссии. Этот сценарий тоже ещё не запускался в игре и может остановиться
на проверке менеджеров/ресурсов. Причина будет в отчёте.

## Логи и ошибки

Обычный сбор автоматический: при ошибках, периодически во время работы
и после выхода. **Пришлите ZIP обоих участников из `reports/`, относящиеся
к одной попытке.** Укажите, кто хост, кто гость, последний видимый этап,
действие перед ошибкой и было ли управление/изображение/звук.

Если процесс аварийно завершился или вы закрыли лаунчер, после закрытия игры
можно запустить `Collect-DebugLogs.cmd`. Он соберёт последнюю зарегистрированную
попытку. Ошибки предзапусковой проверки лежат в `reports/launch-failure-*.json`
или `lab-preparation-failure.json`; при таком отказе ZIP игровой сессии может
ещё не существовать.

Отчёт содержит этапы, версии, идентификаторы объектов, счётчики native шага,
пакетов, камеры и cleanup, журналы игры/UE4SS и текстовые crash receipts.
Сохранения и дампы памяти автоматически не отправляются. Отчёты могут содержать
локальные пути и Steam-имена/ID: передавайте их для отладки, не публикуйте
целиком в открытом доступе.

Для разбора пары ZIP разработчиком: `python analyze_coop_reports.py host.zip
guest.zip --output analysis`. Python нужен только для этого отдельного анализа,
для обычного запуска комплекта он не требуется. Счётчик flight/loaded или
отсутствие ошибок в анализаторе не доказывают успешный совместный полёт.

Отключение: закройте игру обычным выходом, дождитесь завершения лаунчера.
Загрузчик удаляется только из принадлежащей комплекту лабораторной копии,
после проверки его хеша. Для удаления мода сохраните отчёты и нужный `userdata`,
затем сначала удалите **саму точку соединения** `lab-game/Game/Content/Paks`
через Проводник (не её содержимое), после этого папку комплекта.
Не применяйте рекурсивные команды удаления, проходящие внутрь junction.
