Это предварительный экспериментальный релиз для Steam build **25201480**.
Обоим нужен одинаковый adapters-1. В Assets скачивайте
`ac8-steam-coop-r31-development.zip`; Source code содержит только исходники.
**Исправление проверено без запуска игры. Достижение ангара, вылет, камера
гостя и устранение ранее полученного native access violation ещё не подтверждены.**

## Исправлено

В пользовательской попытке compact-2 загрузились главное меню и мод; на хосте
наблюдались связь с гостем и готовность обоих. Переход к ангару остановился
на отсутствии ответов адаптера меню, затем адаптера паузы. Первый дефект —
старый research gate, отсутствовавший в Steam-лаунчере. Второй — строка
из 17 байт в проверке 16-байтового отпечатка функции паузы.

- Явный профильный gate меню из лаунчера и проверенный корень скриптов,
  без включения старого исследовательского evaluator.
- Исправленный отпечаток паузы из офлайн-копии нужной сборки, ограничение
  длины при компиляции и проверка несовпадения. Проверки объектов/сборки сохранены.
- Проверка обоих адаптеров до первого шага в кампанию, без создания самолётов.
- Отказ setup теперь возвращает причину `bootstrap_environment`,
  `bootstrap_module_path`, `bootstrap_process`, `bootstrap_thread` или
  `bootstrap_fingerprint`, если каталог ответа доступен.
- Ответы привязаны к свежей метке запроса; старый успех, дубликаты и
  отсутствующий ответ не принимаются. Неопределённая команда не повторяется.
- Ошибка удержания паузы фиксируется один раз: нет повторных native acquire,
  автоматического продолжения, освобождения объектов или подтверждения restart
  при неподтверждённой паузе. Обычный выход пользователя остаётся доступен.

Причина отдельного завершения процесса с `0xC0000005` без стека не установлена.
Этот релиз не объявляет тот краш устранённым. Сетевые протоколы остаются
room 8 / AC8P v3, физика гостя и backend создания объектов в этом обновлении
не менялись. Локальный файловый протокол паузы обновлён, поэтому DLL/Lua
обязательно обновлять вместе на обоих ПК.

## Обновление без повторного копирования игры

Если compact-2 уже подготовлена:

1. На обоих ПК закрыть игру и прежний лаунчер обычным способом.
2. Распаковать новый ZIP отдельно, затем заменить **только файлы комплекта
   из ZIP** в своей прежней папке. Сохранить `lab-game`, `userdata`, `reports`,
   `evidence` и `save-backups`; игровых файлов в ZIP нет.
3. Выполнить **Validate-Kit.cmd → Validate-Lab.cmd**. `Repair-Lab.cmd` не нужен.

Для старой compact-1 после замены файлов выполнить `Repair-Lab.cmd → Validate-Lab.cmd`.
Для новой папки: `Validate-Kit.cmd → Prepare-Lab.cmd → Validate-Lab.cmd`.
Подготовка копирует около **4,93 GB** обычных файлов; 26 архивов около **145,65 GB**
читаются через проверенную junction только для Paks. Нужно около 5 GB плюс
запас на сохранения/логи. Оригиналы, их атрибуты и ACL скрипты не меняют.
Источник остаётся установленным. Лаунчер удерживает защитные handles до выхода
игры — его окно не закрывать. Junction не является файловой песочницей:
не добавлять/редактировать файлы в Paks. Steam обновлять после выхода.

## Следующая игровая попытка

Хост — `Start-Host.cmd`, гость — `Start-Guest.cmd`; Steam уже открыт.
Каждый нажимает Enter на титульном экране. Хост создаёт лобби и приглашает
друга, оба готовы, хост открывает подготовку миссии. Ограничения прежние:
**задание 6 / «ПИЛОТ» / F-14D гостя вместо Бакстера**, стандартное вооружение.
Хост сам выбирает свой самолёт и двух AI. Гость свою кампанию не открывает.
После ангара нужна новая готовность обоих, затем явный запуск хостом.
Катсцены локальные; пропуск 2/2, закончивший раньше ждёт второго.

В логе ожидаются `mission_adapters_bootstrap_ready`, затем `sync_route_step`.
Если есть отказ, не нажимать переход многократно. Выйти обычным способом,
отправить ZIP хоста и гостя одной попытки из `reports/`, указать последний экран.
Автосбор включён. Полёт, бой и прохождение кампании по автономным проверкам
не считаются принятыми.

## Проверки без игры

[Машинный отчёт](https://github.com/MursikJN/AC8Coop/blob/r31-adapters-1/docs/research/r31-adapters-1-validation.json).

- Новые DLL собраны MSVC x64 `/W4 /WX`; 56 проверок меню, 7 владения паузой,
  17 bootstrap-контрактов. Проверены 17 фиксированных отпечатков офлайн EXE.
- Реальные DLL внутри Python: шесть сценариев отказа bootstrap и две проверки
  реальной границы Lua → DLL с корреляцией меток. Исполняемый файл игры не
  загружался, игровые функции не вызывались.
- 11 проверок окружения лаунчера без старта процесса; Lua проверяет свежие,
  отсутствующие и повреждённые ответы, блокировку повторной команды и ошибки паузы.
- Моделируемый маршрут: кампания → катсцена → ангар → ручной выбор хоста →
  F-14D гостя → новая готовность → единственная команда вылета → ожидание обоих.
  Это проверка кода с искусственными объектами, не прохождение в реальной игре.
- Компактная подготовка, целостность ZIP, экспорты DLL, синтаксис Lua/PowerShell
  и сохранность исходников/профиля проверяются отдельно.

AI-участие и сторонние компоненты: OpenAI Codex, `CREDITS.md`, `runtime/LICENSE`.
В комплекте нет оригинальных игровых файлов, сохранений, дампов или сырых декомпиляций.
