# R7: первый опыт с состоянием второго игрока

Это исследовательский опыт на двух ПК, а не готовый кооператив кампании. R6 уже показала видимую локальную копию без замеченной тряски. R7 подключает числовое состояние другого участника через Steam; живой совместный опыт ещё не подтверждён.

## Подготовка

1. Оба распаковывают весь архив в отдельную папку. Не копируйте его в игру и не запускайте прямо из ZIP. Нужны собственная игра сборки 25201480 и Steam, два отдельных аккаунта. Python, Visual Studio и SDK для запуска не нужны.
2. Выберите одинаковый F-14D, оружие и установленные детали до миссии. Оба должны дойти в своей одиночной кампании до основной части задания 6 после дозаправки. Миссия, ИИ, противники, урон и результат между ПК пока не синхронизируются.
3. Ведущий запускает `Start-Host.cmd`, второй участник — `Start-Guest.cmd`. Каждый вводит SteamID64 ДРУГОГО участника. При первом запуске укажите папку своей игры; путь и ID сохраняются только локально. Оставьте окно запуска открытым.

## Один ограниченный опыт

1. Когда оба находятся в нужном месте задания, скоординируйте свежий F8 на обоих ПК. F8 проверяет объекты и начинает обмен состоянием; самолёт ещё не создаётся. Подготовка действует 120 секунд, поэтому не нажимайте F8 заранее, пока второй ещё загружается.
2. В окне запуска у обоих должно появиться `peer_ready=1`, счётчик `received` должен расти. `waiting_transport` или одна надпись `ready` от native preflight недостаточны. При несовпадении конфигурации создание блокируется; отправьте папки evidence для разбора.
3. Каждый запускает `Review-And-Arm.cmd` из корня пакета. Скрипт отдельно проверит свежий F8, DLL, процесс, участника/поколение и готовность. Только сообщение `ARMED` означает подготовленный токен. Если время истекло или поколение остановлено, штатно закройте оба процесса и начните новую сессию; не пытайтесь обойти проверки.
4. Снимите паузу. Оба нажимают F7 по одному разу в пределах 20 секунд. Первый ждёт разрешения второго; каждый управляет своим штатным самолётом. Движение каждой копии ограничено 15 секундами с момента её создания.
5. Для различимого результата ведущий летит спокойно прямо, второй делает небольшой крен. На машине ведущего копия должна повторять крен второго, а не собственный самолёт. Сообщите наблюдение с обеих машин. Сохранено тестовое смещение **300 м по мировой X, 100 м по Y, 20 м вверх** относительно переданного положения друга; это ещё не точное пространственное совмещение самолётов.
6. F9 с любой стороны прекращает опыт и отправляет остановку второму. После исчезновения копии каждый нажимает F9 ещё раз для проверки фактического удаления. `retired / all_owned_identities_retired` — подтверждение освобождения; `Destroy=true` и визуальное исчезновение сами по себе недостаточны.

Повторного создания в том же процессе нет. При `quarantine` штатно закройте игру. После выхода дождитесь удаления временного загрузчика. `Remove-ReconLoader.ps1 -GameDirectory '<папка с AceCombat8.exe>'` нужен только после прерванного запуска и закрытия игры; он проверяет хеш и не удаляет неизвестные DLL.

## Результаты

Папки сессий находятся в `profiles/ac8-build25201480-r7/evidence`. Для разбора нужны обе стороны: `session.json`, `plane-flight-status.tsv`, `coop-status.tsv`, `coop-config-r7.json`, `connection-events.tsv`, `status.txt`, журналы поз и `plane-flight-cadence-r6.json`. Имя последнего сохранено по формату r6; поле `revision` у r7 соответствует r7.

Формат передаёт только проверенные скалярные поля состояния. Указатели, UE-объекты, SDK-объекты, исходные виртуальные таблицы и нативные часы отправителя не передаются. Приём проверяет Steam-участника, обе сессионные nonce, поколение миссии/копии, последовательность и конфигурацию. Отсутствие принятых состояний дольше 3 секунд, выход участника, остановка или смена поколения прекращают движение и запрашивают удаление; смена локального мира с недоказанным графом может потребовать quarantine и штатного выхода.

Данный опыт не проверяет перезапуск миссии с активной копией, создание новых копий после переподключения, другие модели/оснащение, оружие/урон, авторитет Host над миссией, четырёх игроков или длительный полёт. Сетевые задержки могут влиять на плавность; текущая приёмная модель использует временную метку принимающего ПК для каждого нового принятого состояния.
